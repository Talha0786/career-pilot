# 036 — pgvector ANN index + nearest-neighbor query

**Status:** DONE | **Milestone:** M5

## Objective
`job_postings.embedding` and `career_profiles.embedding` are both `vector(768)` columns with **no ANN index** — the schema comment explicitly deferred this to M5 ("real cardinality needed to choose parameters sensibly"). Add the index via a new migration and add the repository query method M5's matching pipeline needs: given a profile's embedding, return the top-N nearest job postings by cosine distance (the embedding prefilter from docs/06-agent-design.md §3, "embedding prefilter caps volume" before the LLM rubric-scoring pass).

## Files affected
- `packages/infrastructure/src/db/migrations/0004_ann_index.sql` (new) — `CREATE INDEX ... USING hnsw (embedding vector_cosine_ops)` on both `job_postings` and `career_profiles` (pgvector HNSW; use `m=16, ef_construction=64` as defaults unless the existing schema doc's design notes specify otherwise — check `docs/02-database-design.md` for any prior guidance before picking parameters).
- `packages/application/src/ports/repositories.ts` — extend `JobPostingRepository` with `findNearestByEmbedding(embedding: number[], opts: {limit: number, excludeStatuses?: string[]}): Promise<JobPosting[]>` (or similar — match the existing repository method-naming style in that file).
- `packages/infrastructure/src/db/repositories/drizzle-job-posting.repository.ts` (or wherever `DrizzleJobPostingRepository` lives) — implement via Drizzle's pgvector cosine-distance operator (`<=>`), `ORDER BY embedding <=> $1 LIMIT $2`.
- `packages/infrastructure/test/integration/` — new or extended integration test: seed several job postings with distinct embeddings, prove nearest-neighbor ordering is correct against real Postgres+pgvector.

## Dependencies
- 035 (profile embeddings must exist for a meaningful profile→job ANN integration test; the index migration itself has no hard dependency, but write the task as a unit so the integration test isn't testing against always-null profile embeddings).

## Acceptance criteria
- Migration applies cleanly on top of `0003_connectors.sql` (verify via the same `docker compose up -d --build` + migrate-log-check pattern used for tasks 026-032's Docker verification — check migration logs explicitly mention `applying: 0004_ann_index.sql`).
- `findNearestByEmbedding` returns results ordered by ascending cosine distance, respects `limit`.
- No regression to existing job-postings integration tests.

## Test plan
- Integration (real Postgres, real pgvector extension): seed fixtures with known embeddings at known distances, assert exact ordering.
- Full `docker compose up -d --build` verification (matching the migrate-service-staleness lesson learned during the M3/M4 merge — always rebuild ALL services, not just the ones you think changed).
