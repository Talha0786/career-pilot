# 050 — LLM field mapper (fallback) + golden-set eval

**Status:** TODO | **Milestone:** M6

## Objective
Stage 3 of the field-mapping pipeline (`docs/05-playwright-design.md` §4): when heuristics (049) produce low-confidence results, an LLM classifies the serialized accessible form tree into the taxonomy with confidence scores. Per docs/06-agent-design.md's pipeline table, this is a `pipeline`/`mid`-tier/`FieldMap schema` call — "low-confidence → blank + flag", same ADR-006 structured-output discipline as every other M5 LLM call site (zod validate, one repair attempt, then typed failure). Must NOT invent answer content for open/essay questions except as an explicit per-task opt-in draft that always appears in the review diff (task 052).

## Files affected
- `packages/contracts/src/field-mapping.ts` (new) — `FieldMapSchema` (per-field: taxonomy key, selector/element ref, confidence, `neverAutoFill` passthrough).
- `prompts/field-map/v1.md` (new) — follows the `prompts/{task}/{version}.md` convention from task 034 (frontmatter: model_tier, temperature, output_schema ref).
- `packages/application/src/apply/commands/map-fields.ts` (new) — orchestrates: 048 known-ATS detect → 049 heuristics → for remaining/low-confidence fields, guarded `llm.complete()` against `prompts/field-map/v1.md` → zod validate → one repair attempt → typed failure with raw output stored for triage (verbatim ADR-006 rule, same as tasks 038/039/040).
- `packages/intelligence-evals/src/run-field-mapper-eval.ts` (new) + `packages/intelligence-evals/fixtures/field-mapper/*.json` (new) — golden-set eval per `docs/05-playwright-design.md` §7: "LLM mapper | Golden-set eval: form tree → expected taxonomy; regression gate ≥95% on P0 fields." Reuse `buildLlmHarness()`/`writeTimestampedResult()` from the existing `packages/intelligence-evals/src/harness.ts` (built in M5 task 042) rather than a new harness.
- `.github/workflows/nightly.yml` — extend the existing nightly gate (added in M5 task 042) to also run the field-mapper eval.

## Dependencies
- 033 (CostEstimator), 034 (PromptStore), 048, 049 (feeds this stage only the fields the earlier stages left low-confidence/unmapped), 042 (eval harness to reuse).

## Acceptance criteria
- LLM mapper is only invoked for fields the earlier two stages didn't confidently resolve — cheapest-first is enforced with a test (same pattern as task 038's ANN-prefilter enforcement test), not just documented.
- Golden-set eval passes the ≥95% P0-field regression gate from the design doc; if the initial pass rate is below that, iterate the prompt (same anti-hallucination-style buffer the M5 roadmap entry built in for its own evals) rather than lowering the gate.
- Sensitive fields remain untouched even through the LLM path — the `neverAutoFill` taxonomy flag from 048 is enforced post-LLM-response too, not just pre-prompt (defense in depth: don't trust the model to always respect it in the prompt alone).

## Test plan
- Unit: cheapest-first invocation-count enforcement (fake heuristics returning all-confident → zero LLM calls).
- Eval: `run-field-mapper-eval.ts` against the golden-set fixtures, ≥95% P0-field accuracy, real evidence pasted into the Status note (not claimed).
