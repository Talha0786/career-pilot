# 061 — Mock interviewer (agentic chat loop)

**Status:** TODO | **Milestone:** M7

## Objective
Implement the mock interviewer per `docs/06-agent-design.md` §5: "chat loop over (JD + profile + question bank); tools: `get_profile`, `get_job` (read-only). Session transcript stored under `interview_preps`. Turn cap 40; budget-guarded." This is one of only two genuinely agentic (open-ended tool-loop) components in the whole system per §1's "pipelines first, agency last" philosophy — keep the loop itself minimal and tightly bounded, resist scope creep into a general chat feature.

## Files affected
- `packages/application/src/interview-prep/commands/run-mock-interview-turn.ts` (new) — one turn of the chat loop: given the running transcript + JD + profile + question bank (seeded from 060's `generate-questions` output), calls the LLM with `get_profile`/`get_job` as the only available tools (both read-only, reusing 057's MCP tool logic or the underlying queries directly — don't fork a second implementation of the same reads).
- `apps/mcp-server/src/tools/generate-interview-prep.ts` (060's file) — extend to handle `kind: 'mock_interview'`, or add a distinct tool if the design doc implies mock-interview is session-based rather than a single tool call (check whether a running chat session needs a start/continue/end tool triplet vs. one-shot — document the choice; a reasonable design is `generate_interview_prep({kind:'mock_interview'})` starts a session, subsequent turns go through a lighter-weight continuation path since MCP tool calls are typically request/response, not a persistent stream).
- Turn cap enforcement: hard stop at 40 turns, transcript still returned/stored up to that point (not discarded).
- Transcript persisted to 060's `interview_preps` table (`kind: 'mock_interview_transcript'`).
- Every turn goes through `GuardedLlmPort` — no bypass, budget exhaustion mid-session ends the session gracefully (not a crash), same posture as every other M5/M6/M7 LLM call site.

## Dependencies
- 060 (question bank, `interview_preps` table, shared read-only tool wrappers).

## Acceptance criteria
- The loop never exceeds 40 turns — hard cap, tested with a fake LLM that always wants to continue.
- Only `get_profile`/`get_job` are callable from within the loop — no write tool is reachable even if the model attempts to invoke one (test: fake LLM response requesting a write-shaped tool call, confirm it's rejected/ignored, not executed).
- Budget exhaustion mid-loop ends the session with the transcript-so-far intact, not a hard crash or silent data loss.
- Full transcript persists and is retrievable.

## Test plan
- Unit: 40-turn hard cap; write-tool-call rejection from within the loop; budget-exhaustion graceful-end path — all with fakes.
- Integration: real Postgres, a short real multi-turn session against a local LLM (reusing the `intelligence-evals` harness pattern for "real Ollama" testing established in M5), transcript persisted correctly.
