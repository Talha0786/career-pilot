# 049 — Heuristic field detection

**Status:** TODO | **Milestone:** M6

## Objective
Stage 2 of the field-mapping pipeline (`docs/05-playwright-design.md` §4): when no known-ATS adapter matches (048's `detect()` returns false for all four), fall back to label/`name`/`autocomplete`/aria-attribute heuristics mapping arbitrary forms into the same canonical taxonomy.

## Files affected
- `apps/browser-runner/src/heuristic-mapper.ts` (new) — walks a page's accessible form tree, scores candidate fields against the taxonomy (048's `taxonomy.ts`) using label text, `name`/`id` attribute patterns, `autocomplete` values, `aria-label`/`aria-describedby`, and input `type` (email/tel/file). Returns per-field confidence scores, not just booleans — low-confidence fields feed into task 051's "leave blank and flag" behavior.
- `apps/browser-runner/test/fixtures/heuristic-corpus/*.html` (new) — corpus of 100+ real (sanitized) form snapshots per `docs/05-playwright-design.md` §7's testing table ("Heuristic mapper | Unit tests on a corpus of 100+ real (sanitized) form snapshots"). If 100 genuinely distinct real-world forms aren't practically obtainable, document the actual corpus size and composition honestly in the Status note rather than padding with near-duplicates — this is a case where an honest smaller number beats a fake-looking 100.
- `apps/browser-runner/test/heuristic-mapper.spec.ts` (new).

## Dependencies
- 048 (shared taxonomy).

## Acceptance criteria
- Sensitive fields (EEO/demographic/veteran/disability) are never assigned a non-zero auto-fill confidence, even when a form's labels superficially resemble them — same never-auto-fill invariant as 048, enforced independently here since this stage runs on forms the known-ATS maps never saw.
- Confidence scoring is monotonic-sane: an exact `autocomplete="email"` match scores higher than a fuzzy label-text guess (document the scoring rubric, even informally, so 051's "low confidence → blank + flag" threshold is a real decision, not arbitrary).

## Test plan
- Unit tests against the corpus fixtures — precision/recall on the P0 fields (name, email, phone, resume-upload) reported as a real number, not just "looks right."
