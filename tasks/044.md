# 044 — Schema: apply_tasks, apply_task_steps

**Status:** TODO | **Milestone:** M6

## Objective
Add the persistence layer for the ApplyTask state machine (`docs/05-playwright-design.md` §2-3): `apply_tasks` (one row per assisted-application attempt) and `apply_task_steps` (append-only, one row per state transition / browser action, redacted payload + screenshot key), so the browser-runner is stateless and crash-safe (crash → resume or safe abort from Postgres).

## Files affected
- `packages/infrastructure/src/db/migrations/0007_apply_tasks.sql` (new) — `apply_tasks`: `id, user_id, application_id, job_posting_id, document_version_id, stage (enum: draft|mapping|filling|awaiting_review|approved|submitting|submitted|failed|aborted), ats_adapter (nullable), created_at, updated_at`. `apply_task_steps` (append-only, mirrors `stage_transitions` pattern from `packages/domain/src/pipeline/stage.ts`/migration `0001_init.sql`): `id, apply_task_id, from_stage, to_stage, action (nullable — the browser action taken, e.g. field-fill), redacted_payload (jsonb), screenshot_key (nullable), created_at`. FK `apply_tasks.application_id → applications.id`, `document_version_id → document_versions.id`.
- `packages/infrastructure/src/db/schema/*.ts` (wherever the existing Drizzle table defs live — check `packages/infrastructure/src/db/schema.ts` or per-table files, follow whatever the `match_scores`/`document_versions` tables already do) — Drizzle table definitions matching the migration.

## Dependencies
None from M5 (this is a fresh schema addition). Reads the existing `applications` (M2) and `document_versions` (M3) tables for FKs — both already exist.

## Acceptance criteria
- Migration applies cleanly on top of `0006_claim_verification.sql` (next number in sequence, verify no gap/collision).
- `apply_task_steps` is genuinely append-only — no UPDATE/DELETE path in any repository built later in this track; enforce with a DB-level check if practical (e.g. no updated_at column) or document the invariant clearly for task 045 to honor.
- Drizzle schema round-trips (insert/select) in a smoke integration test.

## Test plan
- Integration: real Postgres (Testcontainers/Docker pattern already established) — migration applies, FK constraints hold (reject orphan `application_id`), basic insert/select round-trip for both tables.
