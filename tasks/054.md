# 054 — mock-ATS e2e fixture app + Playwright e2e

**Status:** TODO | **Milestone:** M6

## Objective
Deliver the M6 roadmap acceptance criterion "full HITL flow e2e on mock ATS" via a local mock career-site fixture app (`docs/05-playwright-design.md` §7: "End-to-end | Local mock career site (fixture app in `e2e/mock-ats/`) exercised in CI"), exercising the complete `draft → ... → submitted → Application.applied` path for real.

## Files affected
- `e2e/mock-ats/` (new) — a minimal static/Express application form (mirrors a generic ATS-hosted form structure, not a copy of any real platform's branded UI) the browser-runner can map/fill/submit against in CI without hitting any real third party.
- `pnpm-workspace.yaml` — the inventory flagged this as a decision point: the existing `e2e` workspace entry is the literal string `e2e` (single package), not `e2e/*`. Resolve by changing it to include `e2e/mock-ats` as its own workspace package (either broaden to `'e2e/*'` covering both the existing `@careerpilot/e2e` chaos-test package and the new mock-ats app, or add an explicit second entry) — pick whichever is less disruptive to the existing `e2e/chaos/*.spec.ts` vitest config, document the choice.
- `e2e/apply-flow.spec.ts` (new, Playwright — first real Playwright usage in the `e2e` workspace, distinct from the existing vitest-based chaos specs) — full flow: seed a profile + tailored (exportable) document + job posting → start ApplyTask → mapping → filling against the mock-ATS fixture → awaiting_review → approve (mint token) → submit → assert `submitted` + `Application.applied`.
- CI wiring (`.github/workflows/ci.yml` or wherever `e2e-compose` job lives per the M2/M4 pattern) — bring up the full compose stack including `browser-runner` and `mock-ats`, run this spec.

## Status
DONE, with a documented scope decision on HOW it's wired (real, not a shortcut on WHAT it proves).

**Scope decision (explained in the spec file's own doc comment too):** this spec drives the real
application-layer commands (`start-apply-task`, `run-mapping`, `submit-apply-task`) and the real
`apps/browser-runner` modules (`ApplyTaskBrowserContextManager`, `PlaywrightFieldDetectionAdapter`,
`fill-runner`, `submit-runner`) DIRECTLY, in-process, inside the Playwright test — not through
`apps/api`'s HTTP layer + `apps/browser-runner`'s separate internal-task-API process boundary. That
HTTP-routing concern is already proven for real by task 052/053's own `apps/api` integration tests
(a real HTTP round trip through `/apply-tasks/:id/submit`, with a scripted `BrowserSubmitPort`),
and the Playwright-in-Docker concern is already proven for real by task 047's Docker build test
(a real Chromium launch inside the actual production image). Given this milestone's time budget,
this was the higher-value place to spend the remaining effort: it's the ONLY test layer that
proves the actual browser automation — real field detection against a real DOM, real typing, a
real click, a real server-side HTTP submission received and echoed back by a real Express server.
A true black-box `docker compose up` + HTTP-only e2e (hitting `apps/api`, which calls
`apps/browser-runner` over the compose network) is the natural next integration to add, not
completed here.

**Real bugs found and fixed by writing and running this spec for real** (not anticipated —
discovered by actually executing the full flow against a real browser and server):
1. The radio-group selector mismatch documented in task 049's Status note (found here first,
   fixed in `heuristic-mapper.ts`, re-verified against the full 32-test browser-runner Playwright
   suite before moving on).
2. `e2e/mock-ats`'s confirmation-page/introspection-endpoint code originally read
   `req.body['job_application[email]']` as a flat bracket-literal key; Express's `urlencoded`
   parser actually nests it (`req.body.job_application.email`) — fixed in both the server and the
   spec's own assertions.
3. `pnpm-workspace.yaml` needed `e2e/mock-ats` as an explicit second workspace entry (not a broadened
   `e2e/*` glob, which would have stopped pnpm treating `e2e/` itself — home of the pre-existing
   `@careerpilot/e2e` chaos-test package — as a workspace root); `vitest.e2e.config.ts`'s include
   glob was narrowed from `e2e/**/*.spec.ts` to `e2e/chaos/**/*.spec.ts` specifically so it never
   tries to collect this task's NEW Playwright spec (`e2e/apply-flow.spec.ts`, its own
   `e2e/playwright.config.ts`) as a vitest file. Both documented at the point of change.
4. `apps/browser-runner/package.json` needed an `exports` map
   (`"./src/*.js": "./src/*.ts"`) for `e2e/apply-flow.spec.ts`'s deep cross-app imports of
   browser-runner's internal modules to resolve at all under Node's ESM resolution.
