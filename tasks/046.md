# 046 — Approval token port (single-use, 5-min TTL)

**Status:** TODO | **Milestone:** M6

## Objective
Build the single-use, short-TTL approval token ADR-003 requires: "Approval is a single-use, short-TTL token; the submit path is architecturally unreachable without it." No existing primitive fits — current auth (`apps/api/src/plugins/session.ts`) is a long-lived opaque session cookie with plain `GET`/`DEL`, which has a TOCTOU race if reused for single-use consumption. This task builds the real thing from scratch.

## Files affected
- `packages/application/src/ports/approval-token.port.ts` (new) — `ApprovalTokenPort`: `mint(applyTaskId): Promise<{ token, expiresAt }>`, `consume(token): Promise<Result<applyTaskId, 'invalid' | 'expired' | 'already_consumed'>>`. `consume` must be atomic (single round trip, no separate get-then-delete).
- `packages/infrastructure/src/auth/redis-approval-token.adapter.ts` (new) — Redis-backed, `SET token applyTaskId NX EX 300` for mint (NX guarantees no collision), and a Lua script (or `GETDEL`, available since Redis 6.2 — check the project's pinned Redis image version in `docker-compose.yml`, it's `redis:7-alpine` so `GETDEL` is available and simpler than a hand-rolled Lua script) for atomic single-use consume.
- `packages/domain/src` — decide whether token minting is triggered by an `ApplyTask.transitionTo('awaiting_review' → ... )` domain event or a plain application-layer command; document the choice.

## Dependencies
- 045 (ApplyTask aggregate — token is scoped to one ApplyTask).

## Acceptance criteria
- A token can be consumed exactly once — concurrent consume attempts on the same token: exactly one succeeds, the rest get `already_consumed` (property-test this with `Promise.all`, same rigor as the M5 budget-lock concurrency proofs).
- Expired tokens (past 5-min TTL) fail `consume` with `expired`, never silently succeed.
- Token value itself is opaque and unguessable (`randomBytes`, same standard as the existing session token in `apps/api/src/plugins/session.ts`).

## Test plan
- Unit: fake/in-memory adapter — legality of single-use semantics.
- Integration: real Redis — concurrent `Promise.all` consume race (exactly one winner, exact count assertion), TTL expiry behavior (can use a short TTL override for the test, don't wait 5 real minutes).
